## Tab Name Dimmer: подтверждённые дефекты

### P1. Отсутствующий основной конфиг не восстанавливается из резервной копии

`src/client/java/org/lts/tabnamedimmer/TabNameDimmerConfig.java`, методы `load`, `ensureConfigExists`, `loadBackup`.

Условие: `tab-name-dimmer.json` отсутствует, но валидный `tab-name-dimmer.json.bak` сохранён. `load()` сначала вызывает `ensureConfigExists()`, а тот записывает настройки по умолчанию. Затем чтение нового пустого конфига успешно, поэтому восстановление из `.bak` не выполняется. Группы исчезают из активной конфигурации; последующее сохранение может заменить старую резервную копию пустыми данными.

Порядок вызовов подтверждён в установленном `tab-name-dimmer-1.1.0.jar`. Действующий конфиг пользователя не удалялся и не переименовывался. Рекомендация: проверять резервную копию до создания настроек по умолчанию; тестировать сценарии отсутствующего, повреждённого и полностью отсутствующего набора файлов в отдельном временном каталоге.

### P2. Изменение размера окна теряет несохранённый ввод групп

`src/client/java/org/lts/tabnamedimmer/gui/GroupManagerScreen.java`, `init` и `saveFields`; `GroupMembersScreen.java`, `init` и `saveMembers`.

Условие: изменить название/цвет группы или вручную отредактировать участников, затем изменить размер окна либо переключить полноэкранный режим до возврата из редактора. `Screen.resize()` вызывает перестроение виджетов; редакторы создают поля заново из модели, в которую текущий ввод ещё не перенесён. Название, цвет или список возвращаются к прежним значениям.

Проверены байткод базового `Screen` и отсутствие обработки `resize` в установленных редакторах. В игре сценарий не воспроизводился. Рекомендация: сохранять черновой ввод перед resize; отдельно проверить, что возврат из быстрого добавления не перезаписывает новых участников старым содержимым полей.

## Tab Name Dimmer: проблемы понятности управления

### P2. Переключатель профиля выглядит как выбор активного набора групп

`GroupManagerScreen.init`, `TabNameDimmerConfig.activeProfile`.

Переключатель «Глобальный / Серверный» выбирает только редактируемый профиль. Переход на серверный сразу создаёт копию глобального; возврат к глобальному не удаляет эту копию. При сохранении существующий серверный профиль продолжает полностью перекрывать глобальный. Поэтому изменения глобальных групп могут выглядеть неработающими на текущем сервере.

Это текущая семантика, а не доказанная ошибка сопоставления игроков. В действующем конфиге серверных профилей нет, поэтому данный сценарий сам по себе не объясняет нынешнюю жалобу. Рекомендация: разделить выбор редактируемого профиля и режим наследования/переопределения, показывать активный профиль явно.

### P2. «Готово» внутри групп не применяет изменения

`GroupManagerScreen.onClose`, `GroupMembersScreen.onClose`, `TabNameDimmerConfigScreen.onClose`, `saveAndClose`.

Вложенные экраны меняют черновую копию. Кнопка «Готово» возвращает назад; для применения требуется «Сохранить» на главном экране. Esc на главном экране отменяет весь черновик. При этом Ctrl+S в списке участников сразу сохраняет весь конфиг, то есть момент применения различается между маршрутами.

Рекомендация: явно обозначить возврат без применения и единообразно оформить сохранение. Не менять поведение Esc на автосохранение без сохранения понятной возможности отмены.

### Текущее состояние профиля

- Одна глобальная группа `Default`; серверных профилей нет.
- Перекраска имён выключена, свечение группы включено.
- Режим `ANIMATED_SORT`, активация удержанием Shift.
- AFK-режим `HIDE`: AFK-игроки исключаются из списка.
- Сопоставление выполняется по имени аккаунта, без учёта регистра. Отображаемое сервером прозвище и имя аккаунта могут различаться; маски `*` не реализованы.
- Если игрок входит в несколько включённых групп, применяется одна группа с наибольшим числовым приоритетом. При равенстве приоритетов выигрывает первая в списке. Цвета и флаги нескольких групп не складываются.

Пользовательский список участников в отчёт не включён. Точный сценарий жалобы на группы пока не уточнён; перечисленные дефекты не следует автоматически считать её единственной причиной.

## Остальной профиль

### P2. ChatHeads теряет отдельные алиасы при сохранении GUI

`../ChatHeads/common/src/main/java/dzwdz/chat_heads/config/AliasesGuiProvider.java`, `toStrings` и `toAliases`.

По исходникам, два алиаса одного аккаунта, например `AliasA -> Account` и `AliasB -> Account`, превращаются в одну строку `AliasA AliasB -> Account`. Обратное преобразование сохраняет левую часть как один ключ `AliasA AliasB`, поэтому отдельные алиасы перестают находиться. Рекомендация: выводить отдельную строку на каждый алиас и добавить тест обратного преобразования. Вывод статический, GUI в игре не открывался.

- Устаревший трекер цен Mod Perks выключен (`priceTrackerEnabled=false`). Его одновременную активную работу с Economy в данном профиле не подтверждаю.
