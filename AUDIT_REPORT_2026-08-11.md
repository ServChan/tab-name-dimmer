# Полный аудит Tab Name Dimmer — 2026-08-11

## Итог

Проект имеет небольшую и понятную клиентскую архитектуру, корректно разделяет общий код и совместимые с 26.1.2/26.2 реализации рендера, сохраняет настройки атомарно и не передаёт данные наружу. После исправлений исходники и локализации проходят проверку, а один и тот же код успешно собирается для Minecraft 26.1.2 и 26.2.

Главный оставшийся риск — визуальное поведение сложного режима прозрачности с Iris/Sodium/Voxy и совместимость mixin с BetterTab. Сборка подтверждает сигнатуры API, но не доказывает порядок прозрачного рендера и внешний вид в игре.

## Исправлено в ходе аудита

| Приоритет | Проблема | Исправление |
| --- | --- | --- |
| P1 | `loadIfChanged()` проверял файл конфигурации из нескольких render/mixin-путей. Раз в секунду render thread мог обращаться к файловой системе. | Проверка перенесена в `ClientTickEvents.END_CLIENT_TICK`; render-код читает только готовый in-memory snapshot. |
| P1 | После выключения мода старые веса анимированной сортировки могли временно сохранять изменённый порядок игроков. | При `enabled=false` веса немедленно очищаются и возвращается исходная сортировка. Состояние также очищается при отключении от сервера. |
| P1 | Новая зависимость Lifecycle Events не была бы гарантирована метаданными мода. | Модуль добавлен в Gradle и в `fabric.mod.json`; README теперь честно указывает обязательность Fabric API. |
| P2 | Извлечение текстуры из `RenderType` использовало reflection для каждой отправляемой части модели. Неудачная reflection-попытка могла повторяться много раз за кадр. | Добавлен identity-кэш преобразований, ограниченный 256 типами, включая отрицательные результаты. |
| P2 | `dimOpacity` и `animationSpeed` существовали в JSON, но пользователь не мог менять их через GUI. | Добавлены циклические пресеты видимости модели и скорости сортировки. |
| P2 | Импорт мог синхронно прочитать произвольно большой файл; отсутствие native file dialog могло завершить экран ошибкой линковки. | Размер ограничен 1 МиБ; `LinkageError` и ошибки диалога обрабатываются с локализованным сообщением. |
| P2 | `es_es` и `es_mx` были английскими копиями, а расхождение ключей ничем не проверялось. | Обе локали переведены; добавлена Gradle-проверка одинакового набора ключей для четырёх языков. |
| P3 | README указывал версию 1.0.3 при фактической 1.0.4 и не описывал контур/прозрачность. | Документация синхронизирована с кодом и зависимостями. |

## Проверенные области

### Архитектура и жизненный цикл

- Мод полностью клиентский; сетевого протокола и серверной части нет.
- Опциональный BetterTab mixin включается только при наличии `bettertab`.
- Кэш `PlayerTransparencyTracker` ограничен 512 сущностями и очищается при disconnect.
- Состояние анимированной сортировки очищается при disconnect и полном выключении функции.
- Версионно-зависимый `SubmitNodeCollector` вынесен в отдельные source set для 26.1 и 26.2.

### Производительность

- В `extractRenderState` больше нет файлового I/O, сетевых запросов или обхода мира.
- Сортировка Tab имеет ожидаемую сложность `O(n log n)` и выполняется только при построении списка игроков.
- Reflection в прозрачном рендере теперь амортизирована ограниченным кэшем.
- Оставшаяся точка наблюдения: `hasLineOfSight()` может вызываться для контуров игроков при открытом `Shift+Tab`. На серверах с очень большим количеством одновременно отрисовываемых игроков стоит измерить Spark-профилем и при необходимости кэшировать результат на один client tick.

### Надёжность и данные

- Конфигурация нормализуется: цвет, скорость и opacity ограничиваются безопасными диапазонами; `null` и повторные имена очищаются.
- Сохранение использует временный файл, atomic move при поддержке файловой системы и `.bak`.
- Повреждённый основной JSON восстанавливается из `.bak`, исходный файл переносится в `.corrupt`.
- Импорт ограничен локальным `.txt`; сеть не используется.

### Безопасность и приватность

- Мод хранит только локальный пользовательский список ников и визуальные настройки.
- Ники, содержимое списка и выбранный путь файла не пишутся в лог.
- Команды, токены, HTTP-серверы и удалённая телеметрия отсутствуют.

### UX и доступность

- Поддерживаются левый и правый Shift.
- Ошибочный цвет блокирует сохранение и подсвечивается.
- Ctrl+S сохраняет настройки, Escape отменяет изменения.
- Новая строка списка создаётся автоматически; импорт устраняет дубликаты с учётом выбранной чувствительности к регистру.
- Экран всё ещё требует визуальной проверки на минимальной высоте окна и максимальном GUI scale.

## Доказательства проверки

- Базовая сборка до изменений: `clean test build` для 26.1.2 — успешно.
- После изменений: `clean check build -Pminecraft_version=26.2` — успешно.
- Финальная distributable-сборка: `clean check build` для 26.1.2 — успешно и выполнена последней.
- `verifyLocalization` проверил наличие `en_us`, `ru_ru`, `es_es`, `es_mx` и полное совпадение ключей.
- `git diff --check` используется перед фиксацией результата.
- В `Everything Voxy/latest.log` от 2026-08-11 установленная прежняя сборка 1.0.4 загружалась на Minecraft 26.2 без сообщений, связанных с `tabnamedimmer`. Текущий изменённый JAR в профиль не устанавливался, поэтому это только проверка предыдущего артефакта, а не новых исправлений.

## Оставшиеся риски

1. **P1 — визуальный runtime smoke test.** Нужно проверить все три режима на заполненном сервере, отпускание Shift, левый/правый Shift, выключение мода, reconnect и смену мира.
2. **P1 — прозрачный рендер.** Проверить тело, броню, плащ, элитры и предметы с Iris/Sodium/Voxy, с шейдерами и без них. Reflection по внутреннему состоянию `RenderType` остаётся хрупкой точкой при будущих версиях Minecraft.
3. **P1 — BetterTab.** Mixin зависит от конкретных сигнатур `tab.bettertab.Tools`; необходим отдельный запуск с текущей версией BetterTab и большим списком игроков.
4. **P2 — автоматические Java-тесты.** Сейчас есть проверка сборки и локализаций, но нет unit-тестов нормализации, matching и переходов сортировки. Логику стоит отделить от Fabric Loader path и покрыть тестами.
5. **P2 — доступность.** Нужна проверка narration/focus order, Tab-навигации и маленького окна. Цвет нельзя использовать как единственный сигнал состояния.

## Roadmap нового функционала

### Ближайший релиз

1. Именованные группы игроков: «клан», «друзья», «модерация» с индивидуальным цветом и приоритетом.
2. Профили по серверу с глобальным fallback, чтобы списки разных серверов не смешивались.
3. Быстрое добавление онлайн-игрока из текущего Tab и экспорт/импорт полного JSON-профиля.
4. Настраиваемая клавиша активации и режим toggle в дополнение к удержанию Shift.

### Следующий этап

1. Поиск и фильтр в большом списке настроек, кнопки удаления и очистки дубликатов.
2. Настраиваемая позиция, якорь, колонки и ограничение строк для `EXTRA_HUD`.
3. Дополнительные условия: online/offline, друзья, scoreboard team, префикс/суффикс display name.
4. Диагностический экран совместимости: активные mixin, BetterTab, текущая версия Minecraft, размер кэшей.

### Технический долг перед расширением диапазона версий

1. Заменить reflection в `TranslucentSubmitNodeCollector` на версионные accessor/mixin-адаптеры там, где API позволяет это сделать стабильно.
2. Добавить unit-тесты для matching, sanitize, preset cycling и стабильности сортировки.
3. Создать ручной regression checklist со скриншотами для 26.1.2 и 26.2, vanilla Tab и BetterTab, shaders on/off.

1. Сделать резервную копию установленного JAR и конфигурации.
